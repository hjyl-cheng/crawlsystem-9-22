## 运行方式

Control 状态、诊断事件及 Sink 事实回执在原事务中写入 `telemetry.outbox`。事件仅包含对象身份、结果、计数、指标状态和大小；响应正文、评论、请求凭据均不进入观测主题。独立 `crawl-analytics` 服务发布 `ops.events`，消费到 ClickHouse 并重算受影响的小时/日汇总后，才确认 PG 归档。Kafka 或 ClickHouse 中断时保留未确认事件，恢复后继续处理。

ClickHouse `crawl.events` 采用 ReplacingMergeTree，查询使用 FINAL。汇总从去重后的明细重算，再以 ReplacingMergeTree 替换对应汇总；没有使用会累计重复消息的求和物化视图。明细保留 180 天，小时与日汇总长期保留。存量视频采用单独的 SNAPSHOT 事件，参与质量观察，排除在新增采集量之外。上线前的历史状态按现存计划、诊断和事实回执补录；不存在的历史状态不补造。

控制台新增 `/failures`、`/analytics`、`/quality`、`/storage`；总览趋势接入 ClickHouse。频道详情可进入 `/history/:id`，查看频道订阅与播放量、视频播放/点赞/评论/时长及采样观察，最多读取最近 1,000 条。原 `/errors` 及事件链接继续可用。计划、Agent 历史完成量/耗时与 Data API 历史请求统计改读 ClickHouse；当前执行数量、配额和控制决策仍读取 PG。统计不可用时页面明确展示错误。

超过 179 天的延迟明细不能重算已经到期的历史桶，服务会保留未归档事件并报警，等待人工处理，避免覆盖长期汇总。

## 失败与恢复

失败按工作区、阶段、原因、计划/搜索、执行代次和单元聚合。重复报告先检查报告身份，避免网络重试增加次数。每条记录保留首次/最近发生、发生与尝试次数、重试/恢复时间和操作原因。操作需要 operator 身份、版本与命令 ID；同一命令返回原结果，状态变化要求刷新后重新操作。旧版本失败计划重试也使用当前的持久入库链路。

解析/入库死信携带经过契约验证的原始引用或步骤清单，省略事实与响应正文。有效的执行代次可以重放；已结束/过期/冲突的消息阻止重放。失败计划重试创建新的有截止时间的冻结计划，不复活旧执行。搜索来源重试仍保留 About 准入门槛。搜索暂停期间禁止搜索失败重试。

采集、画像和搜索的失败响应先单独保存到 raw，不当作成功数据通知解析；已有原始对象由统计服务校验字节数和 SHA256 后复制到 `crawl-evidence`，保留 90 天。证据页面只返回白名单内的响应地址、状态、大小、时间和哈希。原对象丢失会明确标记；基础设施故障期间保持待处理状态。

## 清理与权限

每小时执行有批次上限的清理。30 天前结束的计划，只有统计已归档且没有未解决失败时才清理诊断正文和回执事实快照；诊断哈希、计划、回执身份、冻结目标等恢复/幂等记录保留。当前频道、视频、评论对象引用持续保留。解决/忽略超过 30 天的失败移出默认列表，压缩原始引用与清单，证据引用仍可通过原记录访问至对象到期。

Control 继续不能写采集事实，Sink 不能直接读写控制表。事务触发器和固定清理函数以限定的 SECURITY DEFINER 执行，并禁止 PUBLIC 调用。统计服务只通过自己的短期工作负载身份访问专用接口；ClickHouse 区分读/写账户，MinIO 的保留账户只读 raw、读写 evidence。Kafka 授权只覆盖观测、死信及重放主题。

Prometheus 新增归档积压、最早待归档时间、未解决失败和待保存证据指标；归档延迟超过 10 分钟持续 5 分钟、证据等待持续 30 分钟会进入现有告警通道。Loki 在检查实际 5 GiB 卷占用后，从 72 小时改为 168 小时。容量与服务单点限制继续适用：ClickHouse 是单副本；该阶段保证中断后补写，不提供 ClickHouse 节点故障时的即时统计查询。
