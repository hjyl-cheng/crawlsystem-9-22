# D3 用户登录历史与操作审计

已于 2026-10-11 上线并通过真实验收。用户页接入持久登录历史、近 7 日登录成功 / 拒绝趋势、按用户查看记录，以及类型、结果、时间范围筛选和分页。操作审计包括已认证操作员 / 只读用户的写入请求，记录实际工作空间、主体、接口、目标对象、命令 UUID、请求 UUID、时间和 HTTP 结果。Worker 等服务身份的心跳与采集上报不进入用户审计。

## 留存和权限

记录存放在独立 `crawler.console` 控制台库。新增 `database/console/002_audit.sql`，不更改采集库迁移版本或旧业务库 64 表。退出、过期清理、改密和停用不会删除历史；账号列表的最近登录同时读取已成功的登录审计和仍保留的旧会话。

`GET /v1/console/audit` 与 `GET /v1/console/logins/summary` 仅 operator 可读，工作空间由登录身份确定，查询不接受工作空间参数。reader / Worker 均返回 403。用户详情按主体筛选；全局列表保留 CLI 与 Bearer 操作员事件。分页使用毫秒时间与 UUID 的组合游标，避免同一时间记录分页遗漏；一次最多 100 条，查询范围最多 90 天。

趋势按北京时间的自然日统计。上线前未留存的日期显示缺失，而不是零；上线当天只包含开始留存之后的记录。已知账号的失败登录归属账号空间，包含停用账号；未知账号的尝试不保存所输入用户名，也不归属任意用户工作空间。请求的凭据、Cookie、密码、密码哈希、代理参数、整个请求 / 响应正文都不写入审计。

## 写入与故障语义

HTTP 写入先持久化 PENDING 审计意图，再执行命令，最后在发送响应前确认 SUCCESS / REJECTED / FAILED。无法写入审计意图时不执行操作。若操作已提交后结果写入失败，保留原成功响应和 PENDING 记录，页面显示“结果待确认”；不自动重复命令，也不推测成功。此处的成功是接口命令的执行结果，采集计划或业务交付终态需查看对应业务记录。

HTTP 业务库与控制台库不是同一事务，进程异常退出留下的 PENDING 需要通过原命令 UUID / 请求 UUID 和业务模块记录核对。账号 CLI 新建 / 导入 / 改密 / 停用 / 启用在控制台库中与审计原子提交；导入跳过已有账号不制造变更记录。CLI 操作者以实际服务器用户名 `cli:<name>` 留存。应用角色可新增和读取审计，只能更新结果、HTTP 状态和完成时间，没有删除权限或改写原身份的权限。

账号维护继续使用现有 `npm run console:accounts`，新增历史功能不扩大 reader 权限。既有模块的配置前后值与原因记录仍可在相应业务页面查询。
