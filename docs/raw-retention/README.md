# 原始响应按完成状态保留

原始响应不再使用全桶按上传时间过期。成功采集完成、所有当前代次步骤 APPLIED 且每个单元的入库回执匹配后，至少再保留 24 小时。保留时间同时检查计划完成、清单登记和回执入库时间，以最晚时间为准。

活动任务、缺少回执、未归档消息、OPEN / RETRYING 失败、PENDING 证据以及 PENDING / LEASED 重放均阻止删除。只清理成功任务当前代次的原始单元和对应清单。搜索只清理成功代次已登记的页面，要求页面数一致、资格判断和时钟结算完成，另受同样的失败和队列保护。失败原件、历史失败代次、孤立或无法核验的对象继续保留，不按桶龄自动删除。

Control API 判定资格并登记 `telemetry.raw_retention`；analytics 用独立 MinIO 身份分批执行。每次最多领取 100 对象、并发 4、执行预算 40 秒，每批结束后至少间隔 10 秒。2 分钟租约回收中断批次，失败 5 分钟后重试，完成回报幂等。无效清单记为 BLOCKED，保护原件并避免阻塞后续清理。已压缩而缺少解析引用的历史账本也按此方式保护。

删除前核对原始对象长度、解析结果和评论对象存在及长度，删除后 HEAD 必须确认 404。成功路径原始单元不可覆盖；无需重新读取全部原始 JSON。解析结果或评论对象缺失时保留原件。已不存在对象单独计数，不能冒充本次释放空间。

运行凭据仅允许 `crawl-raw/v1/m1-main/*` 与 `crawl-raw/search/v1/m1-main/*` 的读取 / 删除，以及 `crawl-parsed/v1/m1-main/*` 的只读访问；无其他工作空间、失败路径或 parsed / evidence 删除权限。配置凭据时根凭据仅用于 MinIO Pod 内的短期管理操作，不进入应用。解析结果与评论、失败证据原有 90 天生命周期保持；配额仍为 60 / 15 / 5 GiB。

存储页展示明确的 24 小时规则、队列、确认删除大小、原本缺失对象、受阻对象及最近清理时间。容量图依赖 MinIO 后台扫描，因此确认删除大小和桶指标的即时变化不是同一口径。

验证命令：

```sh
npm run check:safe -- raw-retention-unit
npm run check:safe -- raw-retention-integration
npm run check:safe -- typecheck
```

上线流程先保存生产基线与 schema 备份并应用增量迁移 040，再配置专用权限、发布 Control 和 analytics（自动清理关闭）。移除 raw 全桶过期，预览候选、核对保护对象，小批真实删除后开启自动运行。正式库仅用于基线、增量迁移及真实验收；测试仅使用 `.runtime/r3-test.env`。

停止自动清理：`npm run check:safe -- raw-retention-deploy disable`。队列及已入库解析事实保留；需要回滚应用时恢复 `.runtime/raw-retention/previous-*.json` 中的镜像。不要恢复 raw 全桶 14 天规则，否则会绕过任务状态保护。已经按规则删除的原始响应无法从 MinIO 恢复，业务解析结果及评论仍可查询。

实际验收结果在上线完成后记录于本目录 `evidence.json`。
