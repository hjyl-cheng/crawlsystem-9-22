# D4 IP 可用率趋势

IP 资源管理页新增近 7 天 / 近 24 小时趋势，可切换代理可用率与请求成功率，按服务器和服务商筛选。汇总按观测数和请求数加权；空时段留空，单个有效点也能显示。刷新失败保留已读历史并提示错误，恢复后可手动刷新。超过 3 分钟没有新观测时提示陈旧；自动刷新到达现有控制台轮询上限时可手动继续。

## 统计口径

代理可用率为 `(healthy + degraded) / 实际观测次数`。这两个状态都允许代理池接请求；trial、cooldown、failed 不可用。它是节点上报状态的观测比例，不是按秒累计的运行时间，也不是代理库存比例。已禁用、旧分配、陈旧上报和超过 30 秒的未来时间上报不制造样本；节点离线后保留历史，不推测后续状态。

请求成功率为 `(请求增量 - 失败增量) / 请求增量`，主动健康探测不进入采集请求计数。节点重启或重新分配时累计计数重新起算，同一实例只计算新增计数。请求为零或失败增量超过请求增量时百分比为空；无效计数不能制造成功率。页面库存 KPI 明确注明“占全部库存”，服务商当日表原“可用率”改为“请求成功率”。

历史按数据库接收时间记入小时桶，节点时钟不能移动历史。日图按北京时间自然日合并，固定返回 7 个日点；小时图固定返回最近 24 个整点。更早未留存的时间没有数值，不从当前状态补造历史。上线当天的数据只包含开始记录之后的观测。

## 存储和权限

迁移 `035_proxy_availability.sql` 只追加采集库控制表：开始记录标记、观测流去重检查点、按工作空间 / 小时 / 服务器 / 服务商 / 分组聚合的计数。小时聚合与检查点保留 9 天，由节点同步清理。删除代理仍保留聚合；聚合没有代理地址、用户名或密码。既有每日请求统计接口继续兼容。

同服务器同步使用事务锁，库存行按 UUID 顺序锁定，批量读取当前分配和检查点并批量更新。首次并发上报、同轮重复代理、重复 / 乱序序号及被替代启动实例都不会重复计数；旧分配不能改写新节点状态。500 个代理与反向顺序并发重复上报经过数据库验收。

`GET /v1/proxies/availability` 仅 reader / operator 可读。工作空间来自认证身份，查询只接受 `resolution=day|hour`、`server_id` 和 `provider`；机器身份返回 403，工作空间参数等未知查询返回 400。
