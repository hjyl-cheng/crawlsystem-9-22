## 第 1 步：契约决定

**计划类型。** `CreatePlan` 增加 `source_mode: 'youtube'`，以规范频道 ID（`UC` + 22 位）作为目标；handle/链接解析是单独的辅助能力，不放进计划身份。默认需要 ABOUT、VIDEO、AGENT 三个领域。固定样本计划保留，用于联调与故障测试。

**采集范围（冻结在计划输入里）。** 默认值沿用旧系统配置：最近 **30** 个视频、**90 天**内发布；每个视频采**首屏 Top 评论**，最多 20 条。可在创建时收窄或放宽到上限（100 个视频、3650 天、100 条评论）。`reference_time` 为创建时刻，时间窗口按它计算，重试和恢复不会漂移。

**目标冻结（VIDEO）。** 真实频道的视频清单要在执行时才知道，因此 VIDEO 领域分两段：

1. 目标清单：Worker 列出上传视频后提交一次 `targets` 清单（视频 ID、列出时间、截止时间、是否列尽）。Store 在本执行代次内冻结它，之后同一代次不能换清单；Worker 恢复时先读已冻结清单，不重新列举。清单可以为空（频道窗口内没有视频是合法结果）。
2. 视频批次：每批最多 10 个目标，逐批提交并记回执；每个目标要么是完整视频事实，要么是带原因的**不可用标记**（私有、删除、会员、需登录、地区限制等）。所有目标都有结果才算 VIDEO 完成，缺失不会被当成成功。

**AGENT 输入快照。** Worker 从 Control 读取本计划的 Agent 输入（本计划写入的频道资料与目标视频的当前事实）及其 Hash；提交画像时 Store 重新计算同一 Hash，事实已被更新时拒绝（`INPUT_MISMATCH`），Worker 重新读取再算。ABOUT、VIDEO 未完成前不接受 AGENT。

**状态。** 真实计划在全部必需领域完成前为 RUNNING；WAITING 只用于固定样本中 Agent 未接入的情况。缺字段按 `exact / estimated / empty / unavailable / unresolved / disabled` 表达，不填零冒充成功。

**Workflow。** 统一为 `channelPlanWorkflow`，按冻结输入的 `source_mode` 选择固定样本或真实采集路径；业务身份（plan_id、代次、input_hash、workflow_id）不变。
