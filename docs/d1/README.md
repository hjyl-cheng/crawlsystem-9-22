# D1 集中配置

配置管理页使用真实数据库参数，提供 24 个配置项：更新采集 6 项、搜索与准入 10 项、代理规则 6 项、告警阈值 2 项。环境变量只作为没有数据库配置时的初值；部署初始化保留当前运行值。

`GET /v1/config` 返回发布版本、参数和后台读取记录，`POST /v1/config` 发布单项变更，`GET /v1/config/history` 分页读取变更记录。读接口允许 reader/operator；发布只允许 operator，必须带版本、命令编号和原因，高风险项还需显式确认。并发发布只允许一个版本成功，重复命令返回当前配置，同编号不同内容返回冲突。回滚载入该配置最近一条变更前的值，重新填写原因后发布，保留原历史。

更新、导入、搜索领取、候选准入、API 配额和相关页面都按工作区读取数据库配置。调度器每轮扫描使用同一份更新配置；代理节点通过同步协议读取冷却与试用规则，并在下一轮报告已读取版本。迟到的报告不能降低读取版本。页面展示读取时间与版本，超过 120 秒的报告显示待同步。

既有归档延迟和失败证据告警继续使用 Prometheus/Alertmanager 通道，阈值读取 Control API 指标 `m1_config_threshold`，缺少指标时保留原 600 秒/0 项默认值；持续时间仍为 5 分钟/30 分钟。新增业务告警属于阶段 E。

已领取搜索保留冻结参数，已有采集计划继续执行，已有代理冷却截止时间保持。提高 Data API 准入配额不会增加服务商配额。历史候选保留原资格判断。

数据库迁移 32 只新增 `control.runtime_settings`、`control.runtime_settings_history`、`control.runtime_settings_consumers` 三张控制表；采集数据与旧结构业务库不迁移、不重置。运行身份仅获所需读写权限，配置历史只授予查询和插入。

部署工具和检查入口：

- `npm run check:safe -- config-prepare`：在 `.runtime/d1/` 备份采集主库，应用迁移和权限，将 API/调度器一致的当前配置持久化。
- `config-control-image`、`config-deploy`：先更新兼容旧接口的代理管理客户端，再更新 API、调度器；保留 Worker、解析、入库、画像和交付服务。
- `config-monitoring`：验证并更新已有 R5 告警表达式，保留其他规则。
- `config-browser`：真实页面发布归档阈值、核对 Prometheus 采样、回滚、检查调度器与 6 个代理节点读取版本，并验收 reader 与桌面/手机布局。
- `config-layout`：只读刷新截图，等待手机导航收起动画完成，避免截图截取到过渡状态。
- `config-runtime before/after`：核对持续采集、交付、旧 64 表结构和相关服务状态。
