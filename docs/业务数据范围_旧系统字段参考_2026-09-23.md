# 业务数据范围：旧系统字段参考

日期：2026-09-23｜用途：新系统业务字段基线与开发计划依据。

按用户要求，从旧代码和数据库结构梳理频道基础信息、视频、评论及 Agent 分析结果。新系统以这些实际字段为参考设计业务产出，调度、算法、表结构和实现方式可以重新设计。

参考仓库为 `/home/ubuntu/workspace/oldsystem`，分支 `agent/incremental-migration-release`，提交 `e92d9227a5a3847430e5d062bea13227564ee419`。本次核对仓库内建表 SQL、运行时 DDL、采集写入代码、评论归一化代码和 Agent 输出契约；没有查询线上数据库中的实际记录。

## 1. 数据落在哪里

| 业务结果 | 旧系统位置 | 说明 |
| --- | --- | --- |
| 频道基础信息 | `crawler.channels` | 频道当前资料、统计数值、来源、采集时间及管理状态 |
| 视频数据 | `crawler.contents` | 视频/Shorts/直播的元数据、统计、访问条件与来源证据 |
| 评论 | `crawler.contents.comments_first_page` | JSONB 首屏评论；另有评论总数及评论关闭状态 |
| Agent 分析 | `crawler.agent_profiles.metrics_json` | `audience_profile_agent` 下的十项画像结果及其证据 |
| Agent 版本与输入 | `crawler.agent_profiles` 的相关列 | 输入内容身份、模型/分类体系/提示词版本、输出 Hash 和观察时间 |
| 汇总与执行收口 | `crawler.finalized_profiles`、`crawler.channel_runs` | 结果汇总、状态和完成记录；新系统可重新组织 |
| 下游业务投影 | Business 库的 `public.channel_snapshots`、`public.content_snapshots`、`public.channel_profile_facts` 等 | 与采集事实有字段和形状转换；属于交付接口参考 |

DDL 中的列存在不等于每个频道都能获得该值。下面区分数据值、采集证据和执行状态，避免把过程字段误当新增产品能力。

## 2. 频道基础信息

| 信息组 | 旧字段 | 含义 |
| --- | --- | --- |

| 展示资料 | `title`、`avatar_url`、`summary`、`about_description` | 名称、头像、概要与 About 描述 |
| 关键词与页面 | `keywords`、`available_tabs` | 关键词及可见内容页签 |
| 国家 | `country`、`country_code`、`country_canonical_name`、`country_source` | 原始/规范化国家及来源；需要与 Agent 推断来源区分 |
| 注册时间 | `joined_date_text`、`joined_at`、`joined_at_precision` | 原文、日期和精度 |
| 订阅与总量 | `subscriber_count`、`total_view_count`、`total_video_count` | 订阅数、频道总播放量、频道总视频数 |
| 数值证据 | 上述三项各自的 `_text`、`_status`、`_source`、`_observed_at` | 展示原文、解析/可用状态、来源及观察时间 |
| 外部链接 | `external_links`、`external_links_status` | 外部链接集合与是否已观察 |

`status`、`reject_reason`、`removed_*`、`dormant_*`、`latest_run_id`、`ready_for_agent`、`agent_status`、`agent_attempts`、`agent_next_retry_at` 等属于对象生命周期或执行控制。它们的业务目的可保留，新系统无需原样复制旧状态机。

## 3. 视频数据

主要依据：视频表 [S1]、实际写入 [S4]。

| 信息组 | 旧字段 | 含义 |
| --- | --- | --- |
| 内容身份 | `channel_id`、`source_content_id`、`content_key`、`url` | 频道归属、平台视频 ID、旧内部键和地址 |
| 类型 | `content_type`、`content_type_source` | 内容类型及判断依据 |
| 展示资料 | `title`、`thumbnail_url`、`description`、`hashtags`、`keywords` | 标题、缩略图、描述、话题及关键词 |
| 发布时间 | `published_text_raw`、`published_at`、`published_at_status`、`published_at_source`、`published_at_precision` | 原文、时间、解析状态、来源与精度 |
| 时长 | `length_text`、`duration_seconds`、`duration_status`、`duration_source` | 展示时长、秒数及证据 |
| 播放量 | `view_count`、`view_count_text`、`view_count_status`、`view_count_source` | 数值、原文及精确/估算/未决等状态 |
| 点赞量 | `like_count`、`like_count_status`、`like_count_source` | 点赞数与可用性、来源 |
| 评论总量 | `comment_count`、`comment_count_status`、`comment_count_source`、`comments_disabled` | 总评论数、解析/关闭状态与来源 |
| 访问条件 | `access_status`、`access_status_source`、`is_members_only` | 公开、不公开列出、会员、私有、不可用、需登录等状态 |
| 直播时间 | `live_scheduled_at`、`live_started_at`、`live_ended_at` | 计划、开始和结束时间 |
| 描述证据 | `description_status`、`description_source` | 合法空描述、可用性与来源 |
| 评论正文 | `comments_first_page` | 结构见下一节 |
| 观察与解析版本 | `first_seen_at`、`last_seen_at`、`last_enriched_at`、`playlist_last_seen_at`、`player_last_observed_at`、`next_last_observed_at`、`extractor_version` | 发现、详情/评论观察时间与解析器版本 |
| 内部控制与变更 | `run_id`、`position`、`is_recent`、`player_current_hash`、`next_current_hash`、`publication_item_hash`、`last_observation_id`、`video_change_probability`、`raw_json` | 运行、变更与恢复上下文；逐项确定新系统存储方式 |

旧写入代码使用 `(channel_id, source_content_id)` 处理唯一冲突，内容类型可能被更强证据修正。新实体身份设计应覆盖这种情况。

旧 DDL 的 `content_type` 还允许 `post`，但本次核对的本地 Agent 内容合同限定 `video / short / live`。不根据数据库枚举自动扩大第一版内容范围。

## 4. 评论数据

主要依据：评论归一化和 API 补充 [S5]、Agent 输入合同 [S6]。

旧结构保留首屏顶层评论。`reply_count` 记录回复数量；本次核对的首屏结构不代表已经保存全部回复正文。

| 评论页字段 | 含义 |
| --- | --- |
| `version` | 当前结构版本为 1 |
| `collected_at` | 本次评论页采集时间 |
| `sort` | 排序方式，采集/存储支持 `TOP_COMMENTS`、`NEWEST_FIRST` |
| `total_count` | 上游提供的评论总量，可为未知 |
| `returned_count` | 此页实际保存的评论条数 |
| `comments` | 评论对象数组 |

| 单条评论字段 | 含义 |
| --- | --- |
| `comment_id`、`position` | 评论身份与首屏位置 |
| `text` | 评论正文 |
| `author_name`、`author_channel_id`、`author_url`、`author_avatar_url` | 作者显示名、频道身份、地址与头像 |
| `published_at_utc`、`published_text_raw`、`published_at_status` | 发布时间、上游原文及精确/相对估计/未决状态 |
| `is_edited` | 是否编辑 |
| `like_count`、`reply_count` | 点赞数、回复数 |
| `is_pinned`、`is_channel_owner`、`is_verified`、`is_hearted` | 置顶、频道主、认证、被频道主点赞等标记 |

部分路径还记录 `comments_disabled`、`surface`、`resolution`、`fetch_diagnostics`，用于解释评论是否关闭、是否有明确首屏结果及请求恢复情况。API 未提供的标记在其适配输出中可为 `null`。

接口对接需要处理一处已发现差异：采集表允许 `NEWEST_FIRST`，本地 Agent 的 `CommentPageRecord` 只接受 `TOP_COMMENTS`。新系统应明确接收规则或转换方式，不能把另一种排序改名后冒充 Top 评论。

## 5. Agent 分析结果

主要依据：Python 输出契约 [S7]、本地执行适配 [S8]、结果持久化与发布验证 [S9]。

当前契约为 `input_url` 加十项分析字段。以下记录旧系统实际形状，作为新系统的数据语义基线；具体模型与推断算法可重新选择。

| 字段 | 业务含义 | 当前契约形状 |
| --- | --- | --- |
| `country` | 创作者/频道国家或地区画像 | 具体国家/地区文本 |
| `creator_gender` | 创作者性别或团队类型 | `male / female / brand_team` |
| `creator_age_range` | 创作者年龄画像 | 实际为具体年龄整数，字段名虽含 range，并非区间数组 |
| `creator_language` | 创作者主要语言 | 文本 |
| `audience_region` | 受众地区分布 | 5 个国家/地区加 `Other`，各项含 `region`、`percentage`，总和 100 |
| `audience_age_gender` | 受众年龄与性别分布 | `18-24`、`25-34`、`35-44`、`45-54`、`55-64`、`65+` 六组，每组 `male / female` 占比，合计 100 |
| `audience_language` | 受众语言分布 | `language / percentage` 数组，总和 100 |
| `active_subscriber_ratio` | 活跃订阅者比例 | 0～100 的整数百分比 |
| `channel_tags` | 频道标签与分布 | `tags` 为 10 项；`top_5_distribution` 为前 5 项加 `Other` |
| `channel_categories` | 频道分类 | `{level_1, level_2}`，一个一级分类及 1～3 个同分支二级分类 |

持久化位置为 `metrics_json.audience_profile_agent.<字段>`，每项包含：

```text
value        结果值
source       结果来源
confidence   置信等级
evidence     依据
source_urls  来源链接
reason       补充原因
```

本地模型适配还保存 `profile_processing_context`，包括执行器、输入快照 Hash/时间、处理器版本、模型包版本、分类体系版本和诊断。表级另有 `input_content_ids`、`input_content_hash`、`agent_model`、`agent_version_hash`、`taxonomy_version`、提示词版本字段、`current_output_hash` 与观察时间。

这些是已有画像及可追溯信息。受众等推断值应保留估算/来源含义；不能作为 YouTube 后台实测受众统计展示。

`agentConfig.js` 保留的旧提示词示例曾使用分类数组；当前输出 schema、Python 契约和发布验证使用分类树对象。字段设计以实际结构交叉核对，旧说明不能单独作为新契约依据。

## 6. 对新开发计划的具体影响

1. 单频道完整产出按“基础信息 + 视频 + 评论 + Agent 画像”细化，字段清单由本次源码/DDL 核对提供；移除此前误加的视频质量评价方向。
2. M1 建立稳定身份、字段状态/来源/时间、评论结构和 Agent 输入输出版本的契约；新物理表结构单独设计。
3. M2 贯通真实频道数据与 Agent 结果，页面分别显示数据可用性、本轮完成状态和分析状态。必要结果尚未满足时，不显示完整成功。
4. 视频目标范围、评论抓取策略、更新频率和推断实现继续参考旧配置与执行路径形成具体建议；无法从源码确定的产品取舍再列出讨论。
5. `exact / estimated / unresolved / unavailable`、合法空结果、评论关闭等含义要明确，字段缺失不能填零伪装成功。
6. Current 数据、历史、执行回执与 Raw 各自设计保留规则。已有大 JSON、快照和旧任务表的物理布局不直接复制成新系统设计。
7. 下游接口映射参考 Business 库快照 [S10]。例如 Agent 分类在采集侧为树对象，而旧 `public.channel_profile_facts` 的约束包含数组形状；新接口需要版本化映射，不能假定跨库可直接原样写入。
