## 接单与排空

- `POST /v1/workers/:id/pause|drain|resume` 仅 operator 可调用。命令携带 UUID、期望版本、3～500 字的原因；同一个命令重放不重复修改，同版本并发命令只有一个成功。reader 可以读状态和资源。
- 期望状态持久化在采集控制库；Worker 心跳回报应用版本。界面区分等待确认、失联、暂停、排空中和已排空。旧版本 Worker 不可误显示操作成功。
- START 意图租约与 Worker 分配在同一个事务中完成，与操作命令及搜索领取使用同一 workspace 准入锁。暂停立即关闭新增入口；此前已分配的计划仍然执行，包括未确认的 START RPC 重试。
- 新计划走 `原任务队列/workers/稳定 Pod 身份`。分配记录固定，RPC 响应丢失、暂停、进程替换都不改变计划的队列、workflow ID、输入、deadline 或预算。
- 升级期间继续监听原共享队列，完成原计划和取消处理。已有活动上报后记录旧队列计划归属；归属未确认的旧计划结束前不能显示已排空。既有共享队列兼容 Worker 每次最多执行一项活动。
- 排空核对已分配计划的完整终态、Control 中 RUNNING 的搜索租约，以及 Worker 上报的活动和搜索。活动间隙不能当成计划结束。暂停或排空不调用 Worker shutdown，也不取消已执行搜索。
- Worker 停机或证书更换仍由 Temporal 按原执行恢复；稳定 StatefulSet 身份重启后保留暂停状态和队列。跨 Worker 自动接管故障计划仍留在阶段 E。
- 浏览器网关未就绪时不开放新增计划或搜索。网关暂时不可用的搜索按网络错误重试原任务；首次上线暴露的 10 个启动失败仅恢复原任务重试，保留冻结参数、尝试数、失败预算、原始证据与每日计数。

## 资源口径

`GET /v1/workers/:id/metrics` 按 workspace 校验登记 Worker，服务器指标通过固定 Prometheus 查询读取。节点失联、过期样本或查询失败返回空值，进程与任务趋势继续可读。

Worker 进程在心跳中上报 CPU 使用核数及 RSS，包含该进程的 Temporal 协调，排除浏览器网关。在线 Worker 清理超过 25 小时的样本；页面展示最近 24 小时每 5 分钟平均，缺失时段留空，CPU 和内存分别使用自己的轴。计划与搜索按已确认归属的终态计数，旧搜索失败缺少 Worker 归属时不推测补齐；取消不计为失败，不把每次可重试错误当成失败任务。

## 数据与部署

迁移 033 / 034 仅扩展采集库的 Worker 控制状态、固定分配、命令、资源样本和搜索最近领取记录，保持旧业务库 64 表结构。搜索释放租约仍保留执行 Worker，最终失败可以正确归属到任务趋势。部署前保留 custom 格式采集库备份；先升级兼容旧心跳的 API 和 dispatcher，再升级 Worker。Prometheus、代理、解析、入库、画像与业务交付服务不需替换镜像。

使用 `npm run check:safe -- worker-integration` 验证独立测试库中的接单并发、完整排空和旧协议兼容；`execution-temporal` 验证 SDK 的独立队列身份与取消。`worker-browser` 执行真实页面操作和桌面 / 手机验证，异常时恢复接单。运行证据放在 `.runtime/d2/`，其中部署原始对象和数据库备份不提交。
