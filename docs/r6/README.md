## 真实运行发现的修复

1. 画像服务曾拒绝实际返回的 `NEWEST_FIRST` 评论并产生 422。Python 评论契约现在接受 `TOP_COMMENTS` 和 `NEWEST_FIRST`，保留实际排序来源，混合输入的诊断与 provenance 也按实际数据记录。未知排序仍拒绝。
2. 冻结为 `query-clock-1` 的旧搜索重试遇到结果页变化，完成报告遗漏此前已发现的频道。分页接口为旧政策重试返回历史待判资格集合，执行器据此完成资格判断；是否继续翻页仍按当前页的新频道数判断。旧任务使用官方失败重试命令后，事务性领取该指定任务，进行一次有界维护恢复；没有领取其他搜索或解除积压限制。一次代理网络失败后，第 4 次执行成功，原冻结参数保持不变，5 页发现 93 个新候选、61 个合格，搜索时钟结算为 WEEK。这一维护任务与新政策的自动搜索分开计数。
3. 失败导入通过新计划恢复成功后，导入队列仍指向旧失败计划。失败重试现在在同一事务中将对应导入关联到替代计划，成功后变为 `done`。真实频道 `UC46I9nVfjMqV58QdBjvG4CQ` 的替代计划 `07fa3614-7cd4-46c5-ab7d-f7d012e0e92d` 已完成 ABOUT / VIDEO / AGENT，导入为 `done`，原 Agent 失败已解决。相同失败的 Worker 重复诊断通过官方忽略命令记录恢复原因，原失败计划与证据保留。

两次修复部署都先暂停新任务创建、等待在途任务完成，再更新服务并恢复全部自动配置。仅修复导入关联的第二次部署定向构建控制镜像，没有重建无关执行器。Cloudflare 隧道保持原 PID 1882。
