本阶段已完成独立解析、Kafka 入库和持久账本的上线验收。规则见 [推进计划 §0.3b–f、§0.5](../推进计划_2026-10-08.md)。公开入口仍为 https://controversy-roughly-kiss-genealogy.trycloudflare.com/ 。

执行器先把原始响应和步骤清单写入 MinIO，再发布 Kafka 地址。`apps/raw-parser` 重放捕获的 HTTP 响应，不使用执行器的兼容结果，也不补发网络请求。解析器把评论单独写入 `crawl-parsed`，其余事实发布到 `facts.*`。`apps/pg-sink` 在一个事务中写采集事实与 `crawl_data.ingest_units`；控制 API 根据清单与账本确认领域完成、结算时钟。丢失通知由对账程序补发。

迁移 020 / 021 将管理、计划、时钟、代理、账号等控制表移到 `control`，频道资料、画像、视频和入库账本放在 `crawl_data`。控制服务只写控制表，入库服务只写采集表；执行器没有数据库凭据。入库时通过受限函数锁定计划与频道，隔离取消、代次变化和 Agent 输入变化。旧计划与回执保留。

工作流先等待资料和视频的持久账本，再生成 Agent 输入；评论由控制 API 从 MinIO 按需加载。Agent 输出也走原始文件、解析、Kafka 与账本，入库后计划才完成。页面显示清单与已入库数量；评论展开时读取一次，关闭重开复用结果。超过对象保留期时明确显示过期。

已有评论使用 `run-preview-comment-migration.ts` 迁移：逐页条件写入、读回校验字节数 / SHA-256 / 内容后，才条件替换 PG 中未变化的原页。迁完后添加禁止 PG 评论正文的约束。切换前保留完整 PG 备份；不重置共享数据库。`verify-r3-preservation.ts` 核对视频身份、评论总数和旧控制表记录数。
