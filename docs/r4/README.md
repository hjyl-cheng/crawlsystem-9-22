# R4：网页搜索与首次采集准入

当前搜索策略 `query-clock-2-about` 只通过指纹浏览器抓取 YouTube 搜索 HTML 和 continuation JSON，不调用 Data API，也不因 Data API 剩余额度暂停搜索。每页原始响应先存 MinIO `crawl-raw/search/v1/...`，Control 保存对象地址与哈希、频道发现来源；查询原始响应与频道采集的 Kafka 单元使用不同契约。

新频道为 `DISCOVERED`（待验证）。候选准入仍受分类公平轮转、导入缓冲和计划并发限制；首次计划冻结来源 run、订阅门槛及人工放行标记。导入计划使用 R3 独立解析与入库。工作流等待 About 清单和持久账本齐全，Control 用**该计划自己的 About 观测**判断门槛，通过后才允许目标列表、视频和 Agent。Control 导航接口、清单接口及 Sink 均拒绝尚未通过门槛的后续步骤。

订阅未知或低于门槛时，频道资料保留，候选标记未达标，导入标记 `rejected`，计划以 `CANCELLED` 结束并记录明确的 `QUALIFICATION` 业务原因，不产生技术失败。页面显示门槛未通过以及未执行步骤。技术采集失败保留待验证状态，可重新准入或由操作员明确拒绝；人工放行未达标频道必须填写原因，未达标的放行不计入合格新频道。计划创建和人工决策按相同顺序锁定候选与导入记录，已撤回的候选不能开始采集。

## 搜索时钟口径

旧系统 `channelQualification.js` 允许未知订阅的搜索候选等待 snapshot，`worker.js` 将页面资格检查设为 pending，`discoveryPagePolicy.js` 在 snapshot 验证结束后才处理合格结果；技术失败不等同于成功的零结果。R4 延续这一验证顺序，同时保留本项目已确认的搜索时钟规则：新合格频道 ≥3 为每周，1–2 为每月，0 为空跑；连续三次空跑冷却三个月，冷却后再空跑休眠。

只统计这个 run **首次创建**且通过 About 门槛的候选。并发发现或后续重复发现保留来源，不再计入新合格数。待验证候选全部通过、未达标或人工拒绝后，时钟结算一次；未解决的技术失败不推进时钟，也不会开启同一 binding 的新搜索。手动停用的 binding 保持停用。分页延续现有 max_pages / continue_min_new 规则；重复出现于后续页的频道不再作为该页的新产出，原页重放保持原产出。

已冻结 `query-clock-1` 的历史任务继续使用其 Data API 资格路径，历史已成功任务的时钟不重算。迁移 022 为新增状态与记录，保留所有已有数据。

## 有界验收与运行控制

`scripts/dev/verify-r4-preview.ts full|reject` 显式准备一个单页搜索，执行器 `query-once.mjs` 只处理该 run，不领取后续搜索。两个模式分别验证默认 1000 门槛的两视频全量采集，以及验收专用 1 亿门槛的 About 后停止；每个 run 仅准入一个频道，其余验收候选人工拒绝以结束本轮统计。状态文件允许恢复原 run/plan，避免重复创建。

自动搜索、自动候选准入、定时更新、Query Runner 和强制 BR 出口保持关闭。恢复自动运行仍属于 R6。
