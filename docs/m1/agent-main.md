# 主 Agent：公共契约、可靠入库与集成

工作目录：`/home/ubuntu/workspace/crawlsystem-business`

分支：`business/crawler-platform`

共同规则：[M1 协作与验收](README.md)。

## 1. 交付目标

提供执行器和控制台共同使用的业务基础：持久 Plan、统一契约、鉴权、可靠 Ingest/Store、状态查询与全链路集成。负责把其他两个 Agent 的代码接成可运行系统。

本轮范围为 M1 固定样本链路。真实 Full、Update、Discover、API/Agent 执行和业务分发按后续里程碑实现；当前契约需要保留必要的身份、版本、依赖与结果语义。

## 2. 按顺序实施

### MAIN-01：核对并记录开发接入环境

- 检查工作区、分支、现有资料与测试资源，读取旧系统字段参考，复用已经归档的基础设施验收。
- 整理 PG/PgBouncer、Temporal、应用身份与证书的实际接入方式，以及对应版本、资源预算和未完成项。只记录凭据引用。
- 选择可用的隔离开发/测试环境，固定样本限定大小并持久保存或使用可恢复的版本化来源；不依赖暂缓的 S3。

完成证据：环境配置模板、测试资源分配表、实际接入检查结果。无需重新安装外围组件。

### MAIN-02：建立公共工程和 G0 契约

- 按计划中的 TypeScript/Node.js、React/TypeScript 方向验证工具兼容性并固定运行时、包管理器和关键 SDK 版本，建立目录、检查命令、CI 与集中锁文件。
- 从字段参考建立频道、视频、评论、Agent 十项输出的共享结构，区分上游事实与推断结果，包含状态、来源、时间和版本。
- 定义 Plan/Run、冻结输入/目标、Request/Batch、Submission、回执、领域与 Plan 结果、执行代次、错误关联、分页查询和取消语义。具体枚举只在 `packages/contracts/` 维护。
- 明确 M1 固定样本计划的身份、标识及必需领域，防止误标为正式 Full 或真实 Agent 已完成。
- 为创建、读取输入、提交、查询回执、取消、上报阶段/心跳和页面查询提供运行时 schema 与成功/等待/冲突/拒绝示例。
- 定义稳定 Workflow 身份、启动参数与启动适配器接口；声明数据库与 Temporal 的恢复责任。
- 建立最小迁移、约束、索引和测试样本。每个新增数据集登记用途、唯一身份、大小/增长、保留与删除资格。

完成证据：G0 检查通过、代码提交 SHA，以及 `docs/m1/integration-baseline.md` 中的版本和运行说明。此后通知两条分支同步，接口调整由本 Agent 统一发布。

### MAIN-03：实现 Store 与 Data Ingestor

- 实现提交认证、对象授权、载荷限制、schema/Hash 校验、执行代次校验以及幂等与冲突处理。
- 将事实、检查点、APPLIED 回执和必要的可靠义务在同一短事务提交，确保重复与并发重试不会重复产生业务效果。
- M1 可采用 Fast Apply 直接返回 APPLIED；如提供 RECEIVED，必须实际持久接管完整可恢复内容，不能仅记录 Hash 或放入内存。
- 授权与重放分开处理：过期执行不能提交新的非法效果；有查询权限的调用者能查回已经成功提交的原回执。
- 统一锁序与领域收口；确认目标已枚举封口及必需结果满足后才形成合法 Plan 结果。尚未完成的依赖阻止完整成功与正式发布。
- 连接池、事务/请求期限、批量大小有上限；数据库暂不可用时返回可解释结果，客户端重试预算不被重置。

必须通过：共同验收表中的幂等、冲突、越权、确认丢失、过期执行、缺失领域和并发收口测试，使用实际 PostgreSQL 验证关键事务行为。

### MAIN-04：实现 Control API、持久启动意图与查询

- 原子创建 Plan、冻结输入、执行权限和启动意图；后台派发器在事务外调用执行 Agent 提供的启动适配器。
- 启动调用超时/返回丢失时，以稳定 Workflow 身份核对，覆盖“已启动但未记录确认”和“入库后未启动即崩溃”。
- 提供频道/Plan 列表与详情、输入/检查点读取、Submission/Receipt、执行阶段、错误关联、Worker 心跳与节点关系查询。
- 提供幂等创建与带期望版本的取消；先持久化控制意图，再可靠传达取消，最终写入权限由权威 Store 判断。
- 实现至少能区分只读与操作权限的认证/授权接入，使用成熟库及运行环境凭据；页面按钮隐藏不能替代后端授权。
- 实现必要业务指标、结构化日志和关联 ID；关键完成事实来自事务记录。

完成证据：控制台可用的真实 API、权限验证、启动/取消恢复测试。此任务由主 Agent 负责，不交给前端临时直连数据库实现。

### MAIN-05：集成与验收

- 审查另外两条分支的具体提交，检查是否遵守公共契约和文件边界。
- 提供启动脚本与环境模板，先贯通执行链，再接前端；将契约更正统一同步到各分支。
- 跑共同验收表及浏览器关键路径，核对页面、数据库回执和 Temporal 执行的同一业务身份。
- 保存合并版本、验证结果与已知未完成项，在 `docs/m1/reports/main.md` 交付结果。

## 3. 主 Agent 不得遗漏的责任

公共契约、数据库迁移、根依赖、全部控制台后端接口、持久启动/取消意图、权威完成状态、接口变更协调与最终集成均归本 Agent。具体代码可以按模块组织，责任不能悬空。

完成标准：新的隔离环境可按文档启动，固定样本能从创建计划走到可核对的持久结果；中断、重试和取消符合契约；控制台能展示真实过程。未接入的 API/Agent 和真实采集明确列为后续任务。
