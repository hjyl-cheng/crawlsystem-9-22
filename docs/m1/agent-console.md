# 控制台 Agent：真实状态页面与操作体验

工作目录：`/home/ubuntu/workspace/crawlsystem-console`

分支：`business/m1-console`

共同规则：[M1 协作与验收](README.md)。

## 1. 交付目标与边界

让操作人员从页面创建样本计划，查看频道数据、Plan 各领域状态、执行实例、提交回执、等待原因与错误，并在权限允许时取消本轮。

负责 `apps/console/` 及页面测试、运行说明。Control API、鉴权接口、数据库查询、权威状态和公共 schema 由主 Agent 提供。M1 页面服务于内部样本联调；真实采集接入后沿用相同查询契约。

## 2. 开始前

- 确认自己的目录、分支与改动，阅读共同规则、开发计划和字段参考。
- 以主 Agent 的 G0 代码基线、API schema、权限和错误示例为准。接口尚缺时写出具体页面需求和响应示例反馈主 Agent。
- G0 前可整理信息结构与操作路径；暂用的演示数据仅限显式开发/测试模式，不作为接口接入完成的证据。

## 3. 按顺序实施

### UI-01：建立前端基础与 API 接入

- 按 G0 工具链创建 React/TypeScript 应用，导入公共契约，集中管理请求、错误处理和配置。
- 接入主 Agent 提供的身份/权限机制；页面不持有 PG、Temporal 管理或代理供应商凭据。
- 统一实现加载、空结果、未授权、无权限、服务不可用和数据过期提示。
- 轮询有上限与退避，离开页面时取消请求；使用有界分页，不反复读取全量实体或全部执行历史。

完成证据：应用可启动，真实后端查询可用；接口失败能够清楚显示，无法连接时不会自动切到假数据。

### UI-02：频道与 Plan 列表/详情

- 列表支持 G0 约定的过滤和分页，区分测试对象与正式对象。
- 频道详情展示已入库基础信息、视频/评论及 Agent 结果区域，显示来源、采集时间和可用性；缺失或未执行的分析结果显示真实状态。
- Plan 详情展示业务身份、本轮目标与必需领域、各阶段状态、当前等待/失败原因、执行实例与最近回执。
- 区分当前已可用数据、本轮执行结果、Agent 状态与交付状态；未实施的交付显示未启用，不能由采集成功推断已交付。
- 支持创建约定的样本计划以及查询其真实执行记录。必要结果缺失时，界面不能自行推断“完整成功”。

完成证据：页面可跟随一个真实运行的样本 Plan 从创建、等待/执行到结果入库，字段值与查询 API 一致。

### UI-03：Worker/节点与错误视图

- 展示后端已登记的节点关系、Worker 身份、版本、接单状态、最近心跳与失联提示。
- 代理字段只展示实际已接入的数据；固定样本未使用代理时明确显示状态。
- 错误视图显示类别、阶段、首次/最近时间及后端提供的关联 Plan/Worker/节点/回执；能跳到对应详情。
- 指标和计数由后端提供并标明口径/时间，不以当前分页行数冒充系统总量，不从采样日志推断精确完成数。

完成证据：从错误入口能找到对应 Plan 和最近回执；Worker 停止心跳后，页面按服务端契约反映失联。

### UI-04：安全操作与交互验证

- M1 接入主 Agent 已实现的创建和取消操作；提交时携带契约要求的幂等身份/期望版本，避免连点重复操作。
- 取消完成依据后端持久状态展示；遇到版本冲突时提示刷新，保留用户理解当前状态所需的信息。
- 根据权限展示操作入口，后端拒绝时显示明确原因。未实现的重试、暂停、扩容或部署能力不提供可执行按钮。
- 中文文案直接说明正在等待什么、已完成什么以及可采取的操作；按需确认有实际影响的取消操作。

完成证据：只读用户无法执行写操作；过期页面提交能正确处理；用户能完成“创建计划 → 查结果 → 定位失败 → 取消本轮”的已支持路径。

### UI-05：测试与交付

- 页面测试覆盖等待、部分数据可用、完整结果、错误、空结果、无权限、过期状态与网络失败等可观察行为。
- 测试数据来自公共契约并明确标识，快照或组件测试不能代替真实接口验证。
- 使用实际后端完成关键路径 E2E；记录环境、命令、浏览器结果与必要截图，避免截图泄露凭据。
- 提供构建、启动和环境配置说明，更新 `docs/m1/reports/console.md`，在自己的分支提交供主 Agent 集成。

## 4. 完成标准

第一批页面能展示持久业务状态，正确区分数据可用与计划完成，并帮助定位等待/失败。页面没有自行定义的业务枚举、假成功或直接数据库连接；关键操作和权限测试有结果，未接入能力明确列在报告中。
